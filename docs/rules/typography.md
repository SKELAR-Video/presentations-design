# Типографіка

## Шрифт

- **Inter, weight 500** — скрізь і завжди, без винятків.
- **`bold: false`** — абсолютне правило (навіть для заголовків).
- Ієрархія — тільки через розмір кегля, не через жирність.
- **`autofitType: 'NONE'`** — у всіх TEXT_BOX без винятків (Google Slides API v1 не підтримує shrink-on-overflow при записі через API).

## Кроки розміру

Дозволені кроки баді-тексту: **14, 18, 22pt** — інші не вводити без узгодження.

Шкали для автоматичного підбору кегля:
| Елемент | Шкала |
|---|---|
| Заголовок (`ЗАГОЛОВОК` slot) | `[44, 40, 36, 32, 28]` pt |
| Section/closing title (no subtitle) | `[66, 54, 44, 36, 28, 22]` pt |
| Cover title only | `[66, 54, 44, 36, 28, 22]` pt |
| Бенто-картки | `[48, 36, 28, 22, 18, 14, 10]` pt (з обмеженням role max) |
| KPI ЗНАЧЕННЯ | `[48, 36, 28, 22, 18, 14]` pt |

## Word-fit guard

Жодне ціле слово не має виходити за межі ширини боксу.

```
longestWordPx(text, pt) = max(word.length) × pt × 2.667 × CHAR_W
```

- **`CHAR_W = 0.65`** — коефіцієнт ширини символу (Inter Medium, Cyrillic-safe)
- **`SAFETY = 1.1`** — запас безпеки *(було 1.2; зменшено для кращого використання ширини)*
- Умова проходження: `longestWordPx × 1.1 ≤ inner_width`
  де `inner_width = element_width − 2 × _INSET` (_INSET = 19px)
- Пунктуація стрипується з країв слів перед вимірюванням: "активність," → 10 символів, не 11

Логування:
```
[word-fit] <label>: longest_word_len=N | est=NNN | est×1.1=NNN | inner_width=NNN | font=NN → PASS/FAIL
```

## Height check — одна мірка на генератор і валідатор

Висота тексту міряється **однією функцією** — `lib/textfit.ts`. Її імпортують і `lib/google.ts` (щоб обрати кегль), і `lib/validator.ts` (щоб перевірити готовий файл). Дзеркал і копій цієї арифметики більше немає — саме в зазорі між двома «правильними» мірками жили всі баги цієї теми.

```
CHAR_W      = 0.5    — реальна середня ширина символу Inter Medium (з кирилицею)
LINE_FACTOR = 1.1    — lineSpacing 90% × ~1.21em рядок Inter
GAP         = 0.5 × кегль після кожного пункту (spaceBelow)
FIT_MARGIN  = 0.95   — генератор лишає 5% боксу вільними
```

- Генератор: `renderedHeight(...) ≤ inner_height × 0.95`
- Валідатор (`text_overflow`): `renderedHeight(...) ≤ inner_height` (+8px на округлення)

Різниця між ними — **тільки запас**, не формула. Тому PASS валідатора означає «обидва порахували те саме», а не «два схожі розрахунки випадково зійшлись».

**Порожній абзац — це висота, а не порожнє місце.** `formatTitleBodyText` склеює групи через `\n\n`, тому в записаному тексті реально є порожні абзаци, і Slides малює кожен як повний рядок зі своїм `spaceBelow`. І підбір кегля, і `text_overflow` раніше **викидали** порожні абзаци перед вимірюванням — тобто кожен розділювач груп був висотою, за яку ніхто не платив (title_photo: +157px і +243px на слайдах, які «влазили»). Тепер порожній сегмент рахується як один рядок + його відступ (фікстура 10: 2 порожні рядки при 18pt = 154px).

**Ширина і висота міряються різними мірками — навмисно.** Word-fit (чи не вилазить ціле слово збоку) лишається песимістичним `CHAR_W = 0.65 × 1.1`: розірване слово — видимий дефект, а трохи менший кегль — ні.

**Чому 0.5/1.1, а не 0.65/1.2.** Обережний бюджет 0.65/1.2 закладав ~30% лишньої ширини на символ і ~10% на рядок. Пійманий випадок (дек `1iJo-…XbWg`, слайд 6, `three_columns`): картку з 411px реального тексту міряло як 581px, кегль сідав на **11pt** там, де влазить **13pt** — третина картки порожня чисто через арифметику. Фікстура 8 (`npm run validate-fixture`) тримає це число.

`textFits` (одноблочні заголовки, cover/section/kpi/timeline) лишається на старому обережному розрахунку з `lineH` 1.4/1.2: там фіксовані висоти боксів і запас працює на користь. Баді-текст і картки через нього більше не проходять.

## Геометрія має бути одна для підбору кегля і для розкладки

Кегль підбирається під бокс — тому «бокс, під який міряють» і «бокс, у який кладуть» мають бути **однією функцією**, а не двома константами.

Пійманий випадок: `two_columns_timeline` / `three_columns_timeline` розкладаються під **фактичну** висоту заголовка (`buildTimelineLayoutRequests`), а кегль підбирався під захардкоджений найгірший випадок (заголовок 300px → `h=502`). На слайді з однорядковим заголовком реальний бокс — **637px**: 135px (27%) висоти викидалось, шрифт зменшувався даремно. Плюс для 2-колоночного таймлайна колонки різної ширини (674 / 623), а міряло обидві по вужчій.

Тепер обидва шляхи йдуть через `timelineLayoutMetrics(titleText)`, а `bentoDims(compId, ctx)` приймає `{ titleText, tokenIdx }`. Без контексту — попередній найгірший випадок.

Логування:
```
[bento-height] <label>: lines=N | text_height=NNN | inner_height=NNN | font=NN → PASS/FAIL
```

## Заголовки — кроки підбору

Кроки `[44, 40, 36, 32, 28]` pt. Перший, при якому `longestWordPx × 1.1 ≤ _LTW` (де `_LTW = 830px`) — обраний кегль.

`estimateLineCount` з фактором 0.48 використовується **лише** для розрахунку позицій (layout positioning), не для overflow detection.

Фіксовані висоти заголовкових боксів:
| Кегль / Слайд | titleH | textY |
|---|---|---|
| 44pt (cover, bento_right_*, section, badges) | 260px | 420px |
| 36pt (title_body, badges adaptive) | 220px | 380px |

`TITLE_GAP = 60px` — фіксований відступ від фактичного низу ЗАГОЛОВОК до верху ПІДЗАГОЛОВОК/ТЕКСТ на всіх композиціях.

## Інтервали у списках: рядок vs пункт

Правило: **відстань усередині речення менша, ніж між реченнями**. Інакше список читається як суцільне полотно — переніс усередині речення виглядає так само, як межа між двома різними пунктами.

| Що | Значення | Чим задається |
|---|---|---|
| Рядок усередині одного пункту | `lineSpacing: 90` | однаково для всього боксу |
| Проміжок між пунктами | `+ LIST_ITEM_GAP_EM = 0.5 × кегль` | `spaceBelow` (PT) |

Реалізація — `listParagraphStyleRequest()` у `lib/google.ts`.

**Ключове обмеження Google Slides**: `spaceAbove`/`spaceBelow` діють **тільки між параграфами**. Список, склеєний через `\v` (м'який перенос), — це ОДИН параграф, тому єдиним важелем лишається `lineSpacing`, який однаково розсуває і перенос усередині речення, і межу між пунктами. Тому `\v` конвертується у справжній розрив параграфа на записі — `softBreaksToParagraphs()`, 1 символ → 1 символ, щоб не зсунулись FIXED_RANGE-офсети кольорування заголовків.

`\v` лишається внутрішнім маркером пайплайну до самого запису: `splitCardHeader`/`computeHeaderPt`/`findGroupHeaderRanges` розрізняють «`\n` = тут закінчився заголовок групи» і «`\v` = просто наступний пункт».

**Коли застосовується** — `hasListItems(text)`: є `\v` АБО справжній `\n` (композиції `two_columns_plain`/`two_columns_labeled` пропускають `preprocessBentoText`, і їхні пункти приходять окремими параграфами одразу). Виняток — картка «значення + підпис» (`$5M\nнові клієнти`): це не список, два рядки належать разом.

**Проміжок оплачується при підборі кегля.** `textFitsParagraphs` додає `paras.length × 0.5 × кегль` до потрібної висоти. Тому щільна картка отримує **менший шрифт**, а не обрізаний останній пункт. Це свідомий вибір: розділені пункти важливіші за кегль (контент не ріжеться ніколи — див. floor 10pt у `docs/rules/bento.md`).

## Мітка до двокрапки — біла. Вирішує ПОЗИЦІЯ двокрапки в рядку, не довжина

`findColonLabelRanges` — одна реалізація на весь файл. Рядок за рядком (`\n` і `\v` рівноцінні), і мітка разом із двокрапкою стає білою, тіло лишається сірим.

Мітка — це префікс, який є **однією фразою**:

1. **двокрапка закриває рядок** — лід-ін, що анонсує те, що нижче. Білий без обмеження довжини, так само як `findGroupHeaderRanges` фарбує цілі рядки-заголовки;
2. **двокрапка всередині рядка** — мітка, якщо в префіксі **немає коми, крапки з комою й кінця речення** (`, ; . ! ?`) і він не довший за `_COLON_LABEL_MAX = 60`.

**Чому не довжина.** Обидва випадки з реальних деків, 41 і 57 символів. Будь-який поріг між ними — підгонка під два приклади:

```
«Зручні застосунки формують щоденні звички:»            41  ← лід-ін, білий
«Ми зробили це так, щоб усе працювало правильно і надійно:»  57  ← речення, сіре
```

Розрізняє їх **кома**: у другому речення почалось раніше за двокрапку, отже двокрапка — його пунктуація, а не мітка.

Історія — три спроби, дві з них хибні:
- межа 60 → біліла половина речення (дек `1F2YV…ft4ic`);
- межу опустили до 30 → перестав біліти лід-ін на 41 символ (дек `1NUS9…PhXgU`, слот `ТЕКСТ` у `bento_right_2`);
- спроба «двокрапка закриває рядок» не спрацювала: у файлі той лід-ін — один суцільний абзац, а перенос після «звички:» був звичайним переносом по словах при рендері. Візуальний перенос ≠ `\n`; перевіряти треба `paragraph_count` та `soft_breaks` у `inspect-deck`, а не скріншот.

Усі випадки тримають 8 тверджень у `npm run check-colon`, на точних текстах із деків.

**Окремо: `two_columns` і `bento_right_*`** ще й переписують перший `«Мітка: тіло»` у слоті на `«Мітка — тіло»` (крок 2.9). Це про слот, не про колір, і межа там своя — 60 символів, як в усіх шляхів, що вирішують **куди покласти текст**, а не яким його намалювати.

## NBSP — нерозривний пробіл

Короткі слова (1–4 символи: `у`, `і`, `та`, `на`, `до`, `від`, `як`, `це` тощо) не висять у кінці рядка: `addNbsp()` замінює пробіл після них на U+00A0.

- Числові токени — не чіпати.
- `content_integrity` вважає U+00A0 ≡ звичайному пробілу.

## Крапка наприкінці — стрипування

`stripTrailingPeriod()` при рендері прибирає фінальну `.` у:
- `ЗАГОЛОВОК` — всі композиції
- Всі `КАРТКА_N` / `КОЛОНКА_N` — бенто-картки

`?`, `!`, `…`, `...` — **залишати**.

`content_integrity` проходить автоматично (stripped ⊂ original).

## Кольорування тексту з «:»

Правило діє на **всі не-заголовкові текстові слоти** (body, caption, підзаголовки) у всіх композиціях:
- Частина до `:` включно → колір **WHITE** (`#FFFFFF`)
- Частина після `:` → MUTED (`#A2A6B1`) на темному тлі; PINK (`#FCCACA`) на червоному тлі
- `ЗАГОЛОВОК` — завжди виключений

Кольорові токени → `docs/rules/theme-brand.md`.

## Текст не обрізати

**Ніколи** не додавати «…» і не вкорочувати контент мовчки. Якщо текст не влазить — це FAIL валідатора; виправляти треба в промпті LLM або в самому ТЗ, а не в коді обробки.

## Читабельна підлога: 18pt

**Діє на:** усі слоти з баді-текстом (картки, колонки, `ТЕКСТ`) у всіх композиціях. Заголовки мають власні шкали і сюди не входять.

Коли тексту більше, ніж вміщує слайд, зберегти все одночасно неможливо. Втратити доведеться рівно одне з трьох:

| | 1 аркуш = 1 слайд | Текст дослівно | Читабельний кегль |
|---|---|---|---|
| Розкласти на слайди | ✗ | ✓ | ✓ |
| Скоротити текст | ✓ | ✗ | ✓ |
| Лишити як є | ✓ | ✓ | ✗ |

Четвертого варіанту не існує — це арифметика, а не обмеження реалізації. Історично код завжди мовчки обирав третій рядок (кегль падав до 10pt), і слайд виходив газетою, про яку ніхто не питав.

**Правило: читабельність — стан за замовчуванням. Відступ від неї — рішення людини, а не коду.**

**Чому саме 18pt.** Полотно проєкту — 720pt завширшки (1920px ÷ 2.667), тоді як стандартний слайд PowerPoint — 960pt. Тому кеглі тут у 1.33 раза «більші», ніж однойменні там: наші 18pt ≈ 24pt у PowerPoint, класичний мінімум для тексту, який читають із залу. Число виведене з геометрії полотна і загальноприйнятої норми, не з конкретного брифа.

**Смуга допуску: 20%.** Нижче підлоги, але недобір менший за 20% — малюємо меншим кеглем мовчки, людину не питаємо. Причина: питання коштує уваги, і питання заради виграшу в 3% — це шум, від якого люди починають клацати навмання. Поріг у 20% відкалібровано на двох реальних брифах (11 випадків нижче підлоги, з них 4 змістовні); якщо на ширшій вибірці виявиться інакше — правити треба це число, а не сам принцип.

Перевірка з готового файлу — `readable_font` у `docs/rules/verification.md`.

Наслідок для розкладання на слайди → `docs/rules/content-mapping.md`.

## ПІДЗАГОЛОВОК — окреме речення під заголовком

Сутність слайда, не колонки: одне-два речення під заголовком, MUTED-сірим (PINK на червоному), меншим кеглем.

**Кегль — пропорція, не число.** Заголовок сам плаває (44 на плоских колонках, 32/28 на рядах, до 66 на секціях), тому фіксований pt читався б по-різному на кожному слайді. Правило: **0.7 × заголовок**, прив'язане до дозволеної шкали `48/36/28/22/18/14`, підлога 14pt:

| Заголовок | Підзаголовок | Частка |
|---|---|---|
| 66 | 48 | 0.73 |
| 44 | 28 | 0.64 |
| 40 | 28 | 0.70 |
| 32 | 22 | 0.69 |
| 28 | 18 | 0.64 |

**Відстань заголовок → підзаголовок: пропорційна, і міряється від тексту.**

```
titleSubGap = 0.25 × 0.72 × кегль заголовка × 2.667 × 1.1
  66pt → 35px   44pt → 23px   40pt → 21px   36pt → 19px   32pt → 17px   28pt → 15px
```

**Рядок ≠ текст.** Висота рядка (1.1em при lineSpacing 90%) більша за самі гліфи приблизно на 15% — це повітря над великою літерою і під виносним елементом. Якщо міряти низ заголовка по низу рядка, цей фантомний прошарок додається до кожного відступу нижче, і що більший кегль — то більший фантом. Саме тому відстані виглядали різними на слайдах із різним кеглем заголовка. `titleTextBottom` бере повні рядки для всіх, крім останнього, і `_GLYPH_OF_LINE = 0.85` для останнього.

| Кегль | Фантом | Видима відстань було → стало |
|---|---|---|
| 66pt | 29px | 77 → 29px |
| 44pt | 19px | 51 → 19px |
| 36pt | 16px | 42 → 16px |
| 28pt | 12px | 33 → 12px |

**Скільки рядків займе заголовок — рахувати песимістично.** Для підрахунку рядків ЗАГОЛОВКА береться `_TITLE_WRAP_CHAR_W = 0.58`, а не 0.5 з баді-мірки: на 44pt кириличними ця різниця вирішальна. Якорі з реальних деків (44pt, бокс 1610px):

| Заголовок | Символів | Реально | Потрібен коефіцієнт |
|---|---|---|---|
| «Амбасадорська програма» | 22 | 1 рядок | < 0.62 |
| «Підтримка талановитих учнів» | 27 | 2 рядки | > 0.51 |

Помилка в бік «на рядок вище» опускає підзаголовок трохи нижче, ніж треба. Помилка в бік «на рядок нижче» кладе текст на текст — саме це сталося на слайді 24.

Дві причини, чому саме так:
- **Фіксоване число не працює** — обидва кеглі плавають, і 60px під 44pt виглядає інакше, ніж 60px під 28pt. Чверть висоти рядка заголовка тримає однакову оптичну щільність на будь-якому кеглі.
- **Міряти треба від низу ТЕКСТУ, не від зони.** Зона заголовка — фіксовані 245px (плоскі) / 100px (ряди); однорядковий заголовок лишає більшу її частину порожньою. Саме тому відстані «гуляли» від слайда до слайда: візуально це був залишок зони + 60px. Тепер `titleTextBottom` рахує фактичний низ тексту.

Побічний ефект, приємний: коли заголовок і підзаголовок по одному рядку, підзаголовок вміщається в той порожній залишок зони — і колонки не втрачають площі взагалі (`subtitleBand` = 0).

**Підзаголовок — максимум 2 рядки; далі платить він, а не вільний простір.** Той самий обмін, що в бенто-ряду, тільки на рівень вище: відступ під підзаголовком не з'їдається, тому коли речення задовге для свого кегля — **меншає кегль**. Крок вниз по шкалі, поки не влізе у 2 рядки, але ніколи нижче половини заголовка.

Пійманий випадок (дек `1ZB2z…HFJo`, слайд 20): підзаголовок на 28pt розкладався у **3 рядки (246px)** і майже впритул тиснув на колонки. Стало 22pt / 2 рядки / 129px — колонкам повернулось 117px.

Рядки підзаголовка рахуються з `_SUB_WRAP_CHAR_W = 0.62` (не 0.5): на заголовковому кеглі баді-мірка знову оптимістична — вона обіцяла 2 рядки там, де Slides намалював 3.

**Хто платить за висоту: колонки.** Підзаголовок завжди свого розміру; смуга під нього (`subtitleBand` = висота тексту + 60px) віднімається від площі колонок, і якщо треба — їхній кегль падає. Це той самий порядок «спершу площа, потім шрифт», просто площі стало менше. Приклад (аркуш 10, 68 символів, 28pt): смуга 225px → колонки 575 → 350px.

**Розпізнавання у ТЗ — за розташуванням, не за текстом.** `assignSubtitles` (`app/api/fetch-doc/route.ts`) позначає фрагмент підзаголовком, якщо він на всю ширину, нижче заголовка і вище колонок. Це факт розкладки: рядок «Викладачі, голови студпарламентів» текстово не відрізнити від мітки колонки — саме тому він і потрапляв у `ПІДПИС_N`. У промпті фрагмент отримує тег `(підзаголовок)`.

**Слот є лише там, де він рендериться** — 11 колонкових композицій. У `bento_right_*` і таймлайнах його свідомо немає: картки йдуть на всю висоту, місця під підзаголовок без переробки макета нема. Слот, який нікуди не малюється, — це тиха втрата контенту.


## Ієрархія: баді-текст не ближче ніж на 20% до заголовка

Правило «текст росте, поки є вільне місце» без стелі з'їдає ієрархію: на короткому слайді картки доростали до 36pt під заголовком 40pt, і обидва читались як один розмір.

Стеля: **кегль баді-тексту ≤ 0.8 × кегль заголовка** (`hierarchyCapPt`), але ніколи нижче власної підлоги композиції.

```
заголовок 44pt → максимум 35pt
          40pt → максимум 32pt
          36pt → максимум 28pt
          32pt → максимум 25pt
          28pt → максимум 22pt
```

Діє в одному місці для всіх колонкових і бенто-родин (`pickBentoCardPts`) і окремо для `title_body` / `title_photo`. Стара перевірка «текст просто менший за заголовок» цим замінена — «менший на 1pt» ієрархії не створює.

Для `bento_right_*` заголовок береться не з майстра, а з того самого `pickTitlePt`, яким він реально підбирається — інакше стеля рахувалась би від вигаданого числа.

Пійманий випадок (дек `1JVYC…tAek`): слайди 27 (32/28), 28 (44/36), 29 (40/36) → стане 25, 35, 32.


## Заголовок бере простір, який реально є

Кегль заголовка більше не константа макета. Раніше `two_columns` мала 32pt у зоні 100px, `three_columns` — 28pt, плоскі колонки — 44pt у зоні 245px; ці числа описували шаблон, а не слайд. На слайді з короткими картками над ними лишалось 391px порожнечі, бо заголовок про цей простір не знав (дек `1dghU…PYuY`, слайд 13: заголовок 32pt, картки з 551).

Правило одне для всіх колонкових і бенто-родин:

```
верх     y = 100          (мертва зона)
ширина   до 1710          (зона логотипа недоторкана)
кегль    найбільший зі шкали [44, 40, 36, 32, 28], при якому найдовше слово
         влазить у ширину; стеля — 44pt
висота   стільки рядків, скільки вийшло
низ      контент починається на TITLE_GAP=60px нижче фактичного низу гліфів
```

Заголовок бере простір **першим**, контент отримує залишок і, якщо треба, зменшує свій кегль — механізм, який у карток і колонок уже є. Кільцевої залежності немає: заголовок нічого не питає в контенту.

Слайд 13 після зміни: заголовок 32 → **44pt** (2 рядки, 259px), контент починається з 399 замість 551, стеля тексту 25 → **35pt**.

Стеля 44pt (а не 66) — свідомо: контентний слайд не має перетворюватись на титульний.

**Друга стеля — за висотою: `_TITLE_MAX_H = 380px`.** «Бери весь вільний простір» без підлоги під контентом означає, що довгий заголовок з'їдає слайд: чотирирядковий 44pt зайняв 555px і лишив колонкам 323px (дек `1RKZO…KikM`, слайд 9). Тому кегль опускається на крок, поки заголовок не влізе у 380px — це рівно те, що лишається від слайда, якщо контент зберігає свій мінімум:

```
_TITLE_MAX_H = 980 (поле) − 440 (мінімум ряду) − 60 (TITLE_GAP) − 100 (мертва зона) = 380
```

Слайд 9: 44pt → 4 рядки → 516px ✗; 40pt → 469px ✗; 36pt → 422px ✗; **32pt → 376px ✓**. Колонки отримують 458px замість 323.

Явні переноси в заголовку (`\n` із ТЗ) рахуються як окремі рядки — і в підборі кегля, і в розмірі боксу, і в позиції контенту під ним.


## Таймлайни: обмеження зони задає кегль, а не навпаки

`two_columns_timeline` / `three_columns_timeline` тримають зону заголовка не більшою за `TCL_TITLE_HMAX = 300px` — інакше крапки таймлайна виїжджають за слайд. Але кегль був зафіксований на 44pt, тому довгий заголовок потребував 516px усередині 300px-обмеження і просто малювався поверх ряду під ним (дек `1RKZO…KikM`, слайд 11).

Тепер обмеження **задає** кегль: `timelineTitlePt` бере найбільший крок, чия обгорнута висота влазить у 300px.

```
44pt → 4 ряд. → 516px ✗
40pt → 4 ряд. → 469px ✗
36pt → 4 ряд. → 422px ✗
32pt → 3 ряд. → 282px ✓
```

І те саме число, яким виміряли зону, тепер записується в бокс — раніше зона рахувалась одним кеглем, а текст лишався іншим.
