# Типографіка

## Шрифт

- **Inter, weight 500** — скрізь і завжди, без винятків.
- **`bold: false`** — абсолютне правило (навіть для заголовків).
- Ієрархія — тільки через розмір кегля, не через жирність.
- **`autofitType: 'NONE'`** — у всіх TEXT_BOX без винятків (Google Slides API v1 не підтримує shrink-on-overflow при записі через API).

## Кроки розміру

Дозволені кроки баді-тексту: **14, 18, 22pt** — інші не вводити без узгодження.

Шкали для автоматичного підбору кегля:
| Елемент | Шкала |
|---|---|
| Заголовок (`ЗАГОЛОВОК` slot) | `[44, 40, 36, 32, 28]` pt |
| Section/closing title (no subtitle) | `[66, 54, 44, 36, 28, 22]` pt |
| Cover title only | `[66, 54, 44, 36, 28, 22]` pt |
| Бенто-картки | `[48, 36, 28, 22, 18, 14, 10]` pt (з обмеженням role max) |
| KPI ЗНАЧЕННЯ | `[48, 36, 28, 22, 18, 14]` pt |

## Word-fit guard

Жодне ціле слово не має виходити за межі ширини боксу.

```
longestWordPx(text, pt) = max(word.length) × pt × 2.667 × CHAR_W
```

- **`CHAR_W = 0.65`** — коефіцієнт ширини символу (Inter Medium, Cyrillic-safe)
- **`SAFETY = 1.1`** — запас безпеки *(було 1.2; зменшено для кращого використання ширини)*
- Умова проходження: `longestWordPx × 1.1 ≤ inner_width`
  де `inner_width = element_width − 2 × _INSET` (_INSET = 19px)
- Пунктуація стрипується з країв слів перед вимірюванням: "активність," → 10 символів, не 11

Логування:
```
[word-fit] <label>: longest_word_len=N | est=NNN | est×1.1=NNN | inner_width=NNN | font=NN → PASS/FAIL
```

## Height check

```
cpl = floor(inner_width / (pt × 2.667 × CHAR_W))   — chars per line
lines = word-wrap simulation over paragraphs
text_height = lines × FIT_LINE_H(pt) + items × LIST_ITEM_GAP
```

- **`FIT_LINE_H(pt) = pt × 2.667 × 1.2`** (`FIT_LINE_FACTOR`) — висота рядка при підборі кегля
- Умова: `text_height ≤ inner_height` де `inner_height = element_height − 2 × _INSET`

**Чому 1.2, а не 1.4.** 1.4 було правильним бюджетом, поки баді-текст ставився з `lineSpacing: 140`. Зараз він ставиться з **90%**, а рядок при 90% займає ≈ `0.9 × 1.21em ≈ 1.09em`. Залишений 1.4 змушував підбір кегля оплачувати ~28% висоти, яка ніколи не малюється: картка виглядала напівпорожньою, а шрифт усе одно зменшувався. 1.2 — реальна висота плюс запас.

`lineH(pt)` з коефіцієнтом 1.4 навмисно **не змінений**: він ще й ЗАДАЄ розміри боксів (заголовки, kpi), і їх стискання — окрема геометрична зміна.

**Дзеркало у валідаторі обов'язкове.** `_V_FIT_LINE_FACTOR` / `_V_LIST_ITEM_GAP_EM` у `lib/validator.ts` мають збігатись із `FIT_LINE_FACTOR` / `LIST_ITEM_GAP_EM` у `lib/google.ts`. Якщо валідатор лишиться на 1.4, він фейлитиме саме ті картки, яким генератор свідомо дозволив підрости.

## Геометрія має бути одна для підбору кегля і для розкладки

Кегль підбирається під бокс — тому «бокс, під який міряють» і «бокс, у який кладуть» мають бути **однією функцією**, а не двома константами.

Пійманий випадок: `two_columns_timeline` / `three_columns_timeline` розкладаються під **фактичну** висоту заголовка (`buildTimelineLayoutRequests`), а кегль підбирався під захардкоджений найгірший випадок (заголовок 300px → `h=502`). На слайді з однорядковим заголовком реальний бокс — **637px**: 135px (27%) висоти викидалось, шрифт зменшувався даремно. Плюс для 2-колоночного таймлайна колонки різної ширини (674 / 623), а міряло обидві по вужчій.

Тепер обидва шляхи йдуть через `timelineLayoutMetrics(titleText)`, а `bentoDims(compId, ctx)` приймає `{ titleText, tokenIdx }`. Без контексту — попередній найгірший випадок.

Логування:
```
[bento-height] <label>: lines=N | text_height=NNN | inner_height=NNN | font=NN → PASS/FAIL
```

## Заголовки — кроки підбору

Кроки `[44, 40, 36, 32, 28]` pt. Перший, при якому `longestWordPx × 1.1 ≤ _LTW` (де `_LTW = 830px`) — обраний кегль.

`estimateLineCount` з фактором 0.48 використовується **лише** для розрахунку позицій (layout positioning), не для overflow detection.

Фіксовані висоти заголовкових боксів:
| Кегль / Слайд | titleH | textY |
|---|---|---|
| 44pt (cover, bento_right_*, section, badges) | 260px | 420px |
| 36pt (title_body, badges adaptive) | 220px | 380px |

`TITLE_GAP = 60px` — фіксований відступ від фактичного низу ЗАГОЛОВОК до верху ПІДЗАГОЛОВОК/ТЕКСТ на всіх композиціях.

## Інтервали у списках: рядок vs пункт

Правило: **відстань усередині речення менша, ніж між реченнями**. Інакше список читається як суцільне полотно — переніс усередині речення виглядає так само, як межа між двома різними пунктами.

| Що | Значення | Чим задається |
|---|---|---|
| Рядок усередині одного пункту | `lineSpacing: 90` | однаково для всього боксу |
| Проміжок між пунктами | `+ LIST_ITEM_GAP_EM = 0.5 × кегль` | `spaceBelow` (PT) |

Реалізація — `listParagraphStyleRequest()` у `lib/google.ts`.

**Ключове обмеження Google Slides**: `spaceAbove`/`spaceBelow` діють **тільки між параграфами**. Список, склеєний через `\v` (м'який перенос), — це ОДИН параграф, тому єдиним важелем лишається `lineSpacing`, який однаково розсуває і перенос усередині речення, і межу між пунктами. Тому `\v` конвертується у справжній розрив параграфа на записі — `softBreaksToParagraphs()`, 1 символ → 1 символ, щоб не зсунулись FIXED_RANGE-офсети кольорування заголовків.

`\v` лишається внутрішнім маркером пайплайну до самого запису: `splitCardHeader`/`computeHeaderPt`/`findGroupHeaderRanges` розрізняють «`\n` = тут закінчився заголовок групи» і «`\v` = просто наступний пункт».

**Коли застосовується** — `hasListItems(text)`: є `\v` АБО справжній `\n` (композиції `two_columns_plain`/`two_columns_labeled` пропускають `preprocessBentoText`, і їхні пункти приходять окремими параграфами одразу). Виняток — картка «значення + підпис» (`$5M\nнові клієнти`): це не список, два рядки належать разом.

**Проміжок оплачується при підборі кегля.** `textFitsParagraphs` додає `paras.length × 0.5 × кегль` до потрібної висоти. Тому щільна картка отримує **менший шрифт**, а не обрізаний останній пункт. Це свідомий вибір: розділені пункти важливіші за кегль (контент не ріжеться ніколи — див. floor 10pt у `docs/rules/bento.md`).

## NBSP — нерозривний пробіл

Короткі слова (1–4 символи: `у`, `і`, `та`, `на`, `до`, `від`, `як`, `це` тощо) не висять у кінці рядка: `addNbsp()` замінює пробіл після них на U+00A0.

- Числові токени — не чіпати.
- `content_integrity` вважає U+00A0 ≡ звичайному пробілу.

## Крапка наприкінці — стрипування

`stripTrailingPeriod()` при рендері прибирає фінальну `.` у:
- `ЗАГОЛОВОК` — всі композиції
- Всі `КАРТКА_N` / `КОЛОНКА_N` — бенто-картки

`?`, `!`, `…`, `...` — **залишати**.

`content_integrity` проходить автоматично (stripped ⊂ original).

## Кольорування тексту з «:»

Правило діє на **всі не-заголовкові текстові слоти** (body, caption, підзаголовки) у всіх композиціях:
- Частина до `:` включно → колір **WHITE** (`#FFFFFF`)
- Частина після `:` → MUTED (`#A2A6B1`) на темному тлі; PINK (`#FCCACA`) на червоному тлі
- `ЗАГОЛОВОК` — завжди виключений

Кольорові токени → `docs/rules/theme-brand.md`.

## Текст не обрізати

**Ніколи** не додавати «…» і не вкорочувати контент мовчки. Якщо текст не влазить — це FAIL валідатора; виправляти треба в промпті LLM або в самому ТЗ, а не в коді обробки.
