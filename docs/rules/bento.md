# Бенто-картки

## Константи Right Bento

```
RBW = 860   — ширина bento-колонки праворуч
RBH = 880   — висота (H - 2×PAD)
RBX = 960   — PAD + LTW + GAP
LTW = 830   — ширина лівої текстової зони (UW - RBW - GAP)
```

Ліва зона: ЗАГОЛОВОК (44pt, 830×dynamic) + ТЕКСТ (22pt, 830×dynamic) — ТЕКСТ плаває на TITLE_GAP=60px нижче фактичного низу ЗАГОЛОВОК.

**Порожній ТЕКСТ-бокс**: навіть якщо слот відсутній — бокс переміщується нижче ЗАГОЛОВОК (h=1, невидимий). Без цього майстер-бокс залишається на y=390 і перетинає великий заголовок → `bento_left_overlap` FAIL.

## Скруглення кутів

Google Slides REST API **не дозволяє** задати фіксований радіус для `ROUND_RECTANGLE`.

Симуляція: `RECTANGLE` + 4 кути × (квадрат кольору фону + еліпс кольору картки).  
**Радіус: R=30px**, фіксований незалежно від розміру картки.

## Ширина карток

```
cw = floor((UW - (n-1) × GAP) / n)
```

| n карток | cw (px) |
|---|---|
| 1 | 1720 |
| 2 | 845 |
| 3 | 553 |
| 4 | 407 |

Ряд завжди від лівого поля (x=PAD) до правого (x=PAD+UW).

## Шрифт — єдиний pt для групи

Стратегія: **старт від role max**, зменшення якщо текст не влазить.

| Композиція | Role max |
|---|---|
| `two_columns` | 48pt |
| `three_columns` | 28pt |
| `bento_right_2` | 36pt |
| `bento_right_3` | 22pt |
| `bento_right_2x2` | 22pt |
| `kpi_cards` ЗНАЧЕННЯ | 48pt |

По кожній картці знаходимо максимальний pt, при якому текст вміщується. Фінальний груповий pt = **мінімум із них** (найтісніший текст диктує). Застосовується однаковий pt до всіх карток групи.

**Floor = 10pt для ВСІХ композицій без винятку** (`BENTO_MIN_PT` у `lib/google.ts`, дзеркально `FIT_FLOOR_PT` у `lib/anthropic.ts`). Принцип: контент з брифу ніколи не скорочується і не ріжеться — якщо текст задовгий для картки, шрифт падає аж до 10pt, а не композиція підмінюється на `title_body`. Малий шрифт — сигнал людині оцінити на смак (не FAIL валідатора; `bento_layout` фейлить лише нижче 10pt).

Довжина тексту в `КОЛОНКА_N`/`КАРТКА_N` перевіряється у двох місцях, які мають узгоджуватись:
1. `lib/anthropic.ts` (`fitDims` + `fitsAtFloor`) — на етапі маппінгу вирішує, чи лишати композицію з колонками, чи повертати до `title_body` (тільки якщо текст не влазить НАВІТЬ на 10pt).
2. `compositions.ts` `max_chars` — статичний ліміт валідатора; відкалібрований під ту саму 10pt-межу (≈0.65× теоретичної ємності картки, запас на нерівномірний перенос слів).

Якщо колонка проходить (1), але падає на (2) — цифру в `compositions.ts` треба підняти, а не занижувати (1).

`updateTextStyle` виконується **після** `replaceAllText`, не до.

Перевірка: `textFitsParagraphs(text, dims.w, dims.h, pt)` — враховує і word-fit, і висоту.  
Word-fit guard і коефіцієнти → `docs/rules/typography.md`.

## Вертикальне позиціонування (нижній бенто)

Застосовується до `kpi_cards`, `two_columns`, `three_columns`.  
**НЕ застосовується** до `bento_right_*` — в них інша логіка (static grid, `_RBH=880`).

**Правила:**
- Нижній край карток = **980** (H − PAD) — завжди, картки «прилипають» донизу.
- Верх за замовчуванням = **540** (H/2) → мінімальна висота групи = **440px**.
- Якщо контент не вміщується у 440px → верх піднімається вище центру (більша cardH).
- Жорстка підлога: верх ніколи не вище `CY=300`.
- Вільний простір — **тільки зверху карток**, не всередині.

**Формула** (`kCY` = top of cards):
```
contentCardH   = estimated text height + 2×INN + 2×VERT_PAD
desiredTopY    = 980 − max(contentCardH, 440)
kCY            = max(desiredTopY, 300)   // hard floor
cardH          = 980 − kCY
```

Реалізація: `computeKpiAdaptive()` для `kpi_cards`, `buildBentoRowLayoutRequests()` для `two_columns`/`three_columns`.

## Дві змінні ряду: спершу росте картка, потім меншає шрифт

У бенто-ряду є **дві** змінні, і порядок між ними жорсткий:

1. **Висота картки** — від 440px до **680px** (низ прибитий до 980, верх упирається в `CY=300`). Зростити її нічого не коштує → витрачається першою.
2. **Кегль** — падає лише коли картка вже на максимумі. Підлога 10pt.
3. Не вистачило й цього → **FAIL** `text_overflow` з числами. Це design gap: контенту більше, ніж вміщає композиція; рішення за людиною.

**Висота картки і кегль міряються ОДНІЄЮ функцією** — `measuredTextHeight(text, wPx, pt)` у `lib/google.ts`, яка є тонкою обгорткою над спільною мірką `renderedHeightUniform` з `lib/textfit.ts` (та сама, якою валідатор перевіряє готовий файл — див. `docs/rules/typography.md`). `pickBentoCardPts` питає в неї «чи влізе?», `buildBentoRowLayoutRequests` — «якої висоти має бути картка?».

Пійманий баг (деки `1J3ft…DA6Q`, слайди 7 і 15): картку міряли **іншим** розрахунком — `estimateLineCount` рахувала 12 пунктів як один суцільний абзац (7 рядків замість 13) і не знала про відступи між пунктами (160px). Картка лишалась на мінімальних 440px, тоді як шрифт підбирався під 620px → текст вилазив за межі картки і за нижній край слайда на 128px.

`estimateLineCount` навмисно **не змінена** — вона обслуговує заголовки, kpi і таймлайни.

## Плоскі колонки (`two_columns_plain` / `two_columns_labeled`) — той самий принцип

Тут немає картки — **сам текстовий бокс і є колонка**. Майстер ставить його на y=540 (площа 440px): цей відступ намальований під двострічковий заголовок, і кожен слайд платив за нього шрифтом.

Той самий порядок двох змінних, що й у бенто-ряду:
1. **Площа** росте першою: низ прибитий до 980, верх піднімається до `flatColumnsTopMin` — TITLE_GAP=60 під зоною заголовка (245px), плюс 89px смуги `ПІДПИС` для labeled.
2. **Кегль** меншає лише після цього, підлога 10pt.

| Композиція | Верх | Площа (було → стало) |
|---|---|---|
| `two_columns_plain` | 405 | 440 → **575px** |
| `two_columns_labeled` | 494 (мітка на 405) | 440 → **486px** |

- Площа тільки **росте**: 540 лишається підлогою, тому коротка колонка виглядає точно як раніше.
- `ПІДПИС_N` їде разом із колонкою, зберігаючи свою смугу 89px.
- Реалізація — гілка `two_columns_plain`/`two_columns_labeled` у `buildBentoRowLayoutRequests`; та сама функція, що міряє кегль, міряє й площу.

Пійманий випадок (дек `1wit_…3_Tw`): площа 440px пояснювала **кожен** кегль у деку точно — слайди 3/16/10/13/14 → 13/11/13/13/16pt. З виростанням: 16/14/14/15/17pt.

Решта колонкових родин (`three_columns_num`, `four_columns_paren`, `four_columns_bubble`, `columns_flex`) досі на статичних 440px — у них декор (номери, бабли) на фіксованих Y, який має їхати разом; окремий крок.

## Висота картки — за вмістом

`cardH = contentH + 2 × VERT_PAD`

- `VERT_PAD = 40px` для бенто-рядів (`two_columns`, `three_columns`)
- `KPI_VERT_PAD = 30px` для `kpi_cards`
- Усі картки ряду — **однакова висота** (= найвища з них)
- **НЕ розтягувати** картку на весь слайд
- **НЕ розганяти** вміст штучно (`spaceAbove/Below`) — залишки простору знизу коротшої картки

## kpi_cards — tight group

ЗНАЧЕННЯ безпосередньо над ПІДПИСОМ, без пропорційного розподілу:
```
ЗНАЧЕННЯ box:  y = kCY + INN + KPI_VERT_PAD,           h = valH
ПІДПИС box:    y = kCY + INN + KPI_VERT_PAD + valH,    h = lblH
cardH          = valH + lblH + 2×INN + 2×KPI_VERT_PAD
```

kpi_cards геометрія майстра (Figma виміряно):
```
kCY0 = 356  = PAD + TH + subH + TG
kCH0 = 624  = H - PAD - kCY0
kw   = 407  = (UW - 3×GAP) / 4
```

Шрифт ЗНАЧЕННЯ: scale `[48, 36, 28, 22, 18, 14]` pt — найбільший, при якому текст ≤ 3 рядки.

## Буліти

Якщо вміст картки — список пунктів → кожен пункт з нового рядка з маркером `•`.

Автоматична конвертація (`preprocessBentoText`):
- `«пункт1 · пункт2»` → `«• пункт1\n• пункт2»`
- `«рядок1\nрядок2»` (не value+label) → `«• рядок1\n• рядок2»`

**Виняток**: цифра+підпис (`$5M\nнові клієнти`) — не конвертується.

## Що вважається міткою — одне правило на весь дек

`isColumnLabel(line)`: **≤40 символів, ≤5 слів, без крапки/`?`/`!` у кінці**. Цим правилом користуються обидва місця, де виникає питання «це мітка чи звичайний пункт»:
- сіра мітка в плоских колонках (`docs/rules/theme-brand.md`),
- заголовок групи в бенто-картці (`splitCardHeader`).

Раніше `splitCardHeader` мав **відносний** тест: перший рядок мусив бути ще й ≤70% від середньої довжини пунктів. Через це однаковий за роллю рядок був заголовком в одній колонці і звичайним текстом у сусідній — залежно від того, наскільки довгі пункти під ним.

Пійманий випадок (дек `1ZB2z…HFJo`, слайд 9, `three_columns`):

| Колонка | Перший рядок | Середній пункт | Старий поріг | Було | Стало |
|---|---|---|---|---|---|
| 1 | 19 симв. | 32.7 | 22.9 | заголовок | заголовок |
| 2 | 17 симв. | 50.5 | 35.3 | заголовок | заголовок |
| 3 | 32 симв. | 28.7 | 20.1 | **ні** | заголовок |

Мітка — це властивість самого рядка, а не його сусідів.

## Заголовок групи в картці — факт, а не догадка по `\n`

Заголовок групи (біла, трохи більша лід-ін фраза над списком) існує **тільки** якщо його виділив `splitCardHeader` під час препроцесингу. Цей факт **записується** там, де створюється (`bentoHeaderSlots` у `lib/google.ts`), і читається на етапі стилів.

Заборонено виводити наявність заголовка з тексту (`text.indexOf('\n') > 0`). `two_columns_plain` / `two_columns_labeled` **пропускають** препроцесинг (їхня мітка живе в окремому `ПІДПИС_N`), тому їхні пункти лишаються розділені справжніми `\n` — і перший пункт списку читався як заголовок.

Пійманий дефект (дек `1ego0…5KRw`): `all_fonts=[22,14]` у **8 боксах з 8** на 5 колонкових слайдах — перший пункт на цілий крок (+8pt) більший за решту списку. Вигадана ієрархія: перший пункт кричить, ніби він головний. На слайді 14 та сама надбавка ще й виштовхнула текст за межі картки (`text_overflow` +57px).

Перевірка з файлу: `all_fonts` у `scripts/diag-spacing.js`. У боксі списку має бути **один** кегль. Два кеглі = або справжній заголовок групи, або цей баг.

## two_columns_labeled — підпис колонки (ПІДПИС_N)

`ПІДПИС_1`/`ПІДПИС_2` — мітка-категорія над колонкою, окремий слот (тільки в `two_columns_labeled`).

- Висота зони мітки = 89px (від y=451 до y=540, де починається `КОЛОНКА_N`) — не 50px з майстра (той розмір нецентральний, лишений для сумісності з `create-master`).
- Кегль підбирається автоматично через загальний auto-shrink цикл (`FONT_STEPS = [22, 18, 14, 10]`), обмежений floor'ом і цією реальною висотою 89px — не фіксований 22pt.
- `max_chars = 90` — відкалібровано під 2 рядки при 10pt у колонці ~835px.
- При переході в композицію без окремого слоту під підпис (варіанти `two_columns`/`two_columns_plain`/`two_columns_timeline`/`bento_right_2`) — текст підпису приклеюється до `КОЛОНКА_N`/`КАРТКА_N` як `"Підпис — тіло"`, не губиться. Деталі → `docs/rules/compositions.md`.

## Авто-нумерація (bento_right_* з числами)

Числові бенто (`bento_right_2_num`, `bento_right_3_num`) — додаткові константи для розміру числа та відступів:
```
_NUM_PAD      = 11    — відступ від краю картки до числового боксу
                        (INN - _INSET = 30 - 19 = 11, щоб visual top = visual left = 30px)
_NUM_H        = 100   — висота числового боксу (2 картки)
_NUM_GAP      = 30    — відступ між числом і текстом
_NUM_FONT_PT  = 37    — кегль числа (2 картки)
_NUM_H_3      = 70    — висота числового боксу (3 картки)
_NUM_GAP_3    = 20    — відступ (3 картки)
_NUM_FONT_PT_3= 26    — кегль числа (3 картки)
```

Для 3+ карток автоматично використовуються менші значення (`_NUM_FONT_PT_3`, `_NUM_H_3`).
